### 2.2 H 方复核发现的 Z 方事实性错误

**P1-5 / ZB-10：「admin 写入丢弃 sanitize 结果 → 未清洗数据入库」不成立。**

`sanitize_user_record_data`（`domain/rewards.py:210-242`）是**就地修改**：它对 `data["rewards"]`、`data[key]`（8 个装备字段）、`data["equipped_artifacts"]`、`data["immortal_seeds"]` 直接重新赋值，末尾 `return data`。因此 `admin.py:327` 丢弃返回值**不会**导致脏数据入库。

- 裁决：该条从 **P1 降级为 P3 防御性写法**（建议显式接收返回值，防止未来函数改成纯函数时静默失效），工作量维持 0.1 天。
- 影响：不改变任何 P0 结论，但说明 Z 方在"看返回值风格"处未追进函数体，属于局部复核深度不足。

### 2.3 数字偏差

`constants.py:151` 的 `REALMS` 列表经 AST 解析为 **35 项**（索引 0–34），Z 方记为"共 36 境"。差 1，疑似口径差异（是否计入初始态/终态）。不影响 `2^N` 曲线与"终盘渐近"的结论方向，但引用时应更正为"35 个境界条目"或注明计数口径。

### 2.5 三处分歧的裁决

| 分歧 | Z 方 | H 方 | 裁决 |

### 2.6 融合产生的实质增益（两份报告都没有的）

**避免重复改造**：Z 方 ZB-6（聊天计数器内存聚合 + 30s 批量落盘）与 ZB-8（mystic 状态缓存）都依赖存储形态，若在 JSON 阶段实现、迁 SQLite 后需重写为 upsert / 事务缓存。综合计划把这两项**移到 SQLite 迁移同期**，阶段 1 只做与存储无关的治理（接口缓存、渲染卸载、配置校验），减少一次返工。

## 6. 验收总表（发布/上线门禁）

| 类别 | 判据 |
|---|---|
| 安全 | 无 token 访问任意 `/api/*` → 401；`/openapi.json` → 404；`?token=` 不出现在响应；错误 token 触发退避 |
| 数据完整性 | 并发 1000 次写零丢失零损坏；同一玩家并发 50 次账目守恒；损坏/OSError 时插件报错且**不写回** |
| 生命周期 | 优雅停机两个后台任务均取消；每日结算幂等 |
| 迁移 | 31 名玩家关键字段迁移前后逐条一致；单玩家读写耗时不随玩家总数增长 |
| 性能 | `/api/items` 二次请求走缓存；渲染期间 event loop 可响应；首屏 JS 体积下降 |
| 工程 | PR 触发 ruff/mypy/pytest/vitest/build/wheel 校验；README 命令可直接执行 |
| 发布（条件） | 干净 venv 安装 wheel 后秘境事件与签到日历可用；PyPI 有实际发行 |
