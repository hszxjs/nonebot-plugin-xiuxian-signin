# 秘境走格子副本重做设计

日期：2026-07-16

## 目标

将现有“最多探索 10 次后自动退出”的秘境玩法直接替换为可持久化的走格子副本：

- 提供单人入口和 2–3 人团队入口。
- 每种秘境使用固定的不规则节点地图，节点数量随 Boss 修为在 24–48 格之间动态变化。
- 玩家投六面骰决定前进点数，只结算最终落脚节点。
- 团队成员共享一张地图和一个位置，由队长投骰并选择岔路。
- 普通秘境使用中等分岔网络，高风险秘境使用高密度网络并允许有限环路。
- 节点类别可见，具体事件内容在落脚后揭晓。
- 遭遇战复用普通斗法属性和技能规则，怪物由 Bot 控制，全部战斗操作在私聊进行。
- 普通多人遭遇战允许一人或多人应战，并共享同一条怪物血量。
- 多人 Boss 总血量为单人基础血量的队伍人数倍，并按人数分段。
- 玩家有 60 秒配装时间，之后进入不限回合的 PVE 战斗。
- 玩家境界索引严格高于怪物境界索引时，可以选择自动战斗。
- 所有副本奖励进入个人临时奖励账本，击败终点 Boss 后才转入正式资产。
- 每次投骰后向来源群发送更新后的完整地图图片。
- Web 后台可配置地图档位、节点概率、怪物倍率、各类超时和地图资源。

## 非目标

- 不实现完整事件溯源或副本回放系统。
- 第一版不提供可视化拖拽地图编辑器，地图模板通过代码或结构化资源维护。
- 不重写现有玩家 PVP 普通斗法交互。
- 不增加新的运行时第三方依赖。
- 不兼容、不迁移、不补偿旧版“10 次探索”进行中状态。

## 已确认的玩家体验

### 单人入口

- 玩家选择普通或高风险秘境后，校验并消耗自己的对应秘境令牌。
- 令牌在副本状态原子创建成功时才扣除。
- 单人模式使用与团队模式相同的副本引擎，视为只有一名成员的特殊队伍。
- 每名玩家同一时间只能参加一个活动秘境或一场与秘境冲突的私聊战斗。

### 团队入口

- 团队入口只能在群聊创建，来源群绑定整个副本生命周期。
- 队长选择普通或高风险秘境并建立房间。
- 队伍总人数固定为 2–3 人，成员在群中加入并确认准备。
- 只有队长消耗一枚对应难度的秘境令牌，其他成员免费进入。
- 开本前成员可以退出或更换；正式开始后锁定成员名单，不允许补位或替换。
- 成员离线不会被移出队伍，副本和席位均保持可恢复。
- 队长超过可配置的无操作时限后，其余固定成员可以投票将队长权限转给其中一人。
- 队长转让只改变控制权，不改变成员名单、地图位置、奖励或战斗状态。

### 地图移动

- 地图由随机感较强的不规则节点和连线组成，不使用规则方阵。
- 骰子为 1 到 6 点，每经过一条连线消耗 1 点移动点数。
- 单一路线自动继续移动。
- 到达分岔点时暂停，保存剩余点数，等待队长选择路线。
- 选择路线后继续消耗本次剩余点数。
- 只有最终落脚节点触发事件，经过节点不触发事件。
- 到达 Boss 节点时立即停止，多余点数作废。
- 高风险地图允许有限环路；已结算节点再次落脚时不重复触发事件或奖励。
- 单人由玩家本人投骰和选路；团队只有当前队长可以投骰和选路。
- 副本处于应战、配装、战斗、救援或投票阶段时禁止继续投骰。

### 地图信息

- 节点类别图标提前公开。
- 具体怪物、奖励数值和事件结果在落脚后揭晓。
- 已走过的连线显示为绿色。
- 当前节点到所有合法下一节点的连线显示为红色。
- 更远的未探索连线显示为灰白色虚线。
- 不显示方向箭头。
- 每次投骰结算后向来源群发送完整地图、骰点、落脚事件和临时奖励摘要。

### 节点美术

- 普通节点统一为 20x20 逻辑尺寸。
- 随机事件节点使用半透明问号图标。
- 战斗节点使用半透明双剑图标。
- 资源节点使用绿色半透明箱形图标。
- 单人当前位置使用 20x20 小型阴阳八卦阵。
- 团队当前位置使用同一阴阳八卦阵，并附带 `2/3` 人数标识。
- Boss 节点使用 25x25 对应妖兽头像。
- Boss 头像上方显示独立的 BOSS 红色闪电透明 sprite。
- BOSS 特效不进入节点碰撞尺寸，不遮挡路线连线。

## 架构

采用持久化“副本主会话 + 战斗子会话”架构。单人和团队共用领域服务，不复制地图、事件、奖励或战斗逻辑。

### `mystic_dungeon.py`

负责副本主会话和地图领域逻辑：

- 单人和团队房间创建、令牌校验与成员锁定。
- 地图模板、节点图和活动子图加载。
- 节点内容实例化。
- 投骰、移动、分岔暂停和继续移动。
- 队长权限、队长转让和阶段校验。
- 节点事件、个人临时奖励和副本最终结算。
- 副本状态恢复和超时任务协调。

主要类型：

- `DungeonMapTemplate`
- `DungeonNodeSlot`
- `DungeonEdge`
- `DungeonThemeDefinition`
- `MysticDungeonRun`
- `MysticDungeonMember`
- `DungeonRewardLedger`
- `MysticDungeonService`

### `mystic_battle.py`

负责秘境 PVE 战斗协调：

- 普通遭遇战应战、共享怪物血量和多人接力。
- 私聊配装、行动截止时间和 Bot 反击。
- Boss 总血量放大、分段、续战投票和跨分段协助。
- 自动战斗资格和无限回合伤害增幅。
- 普通 PVE 求救衔接。
- 战斗并发锁、幂等行动和唯一结算。

主要类型：

- `DungeonEncounter`
- `DungeonBattleParticipant`
- `BossHealthSegment`
- `DungeonVote`
- `MysticBattleService`

### `mystic_cards.py`

负责秘境地图图片渲染：

- 背景母版裁剪和缩放。
- 连线状态绘制。
- 节点图标、单人或团队八卦阵、Boss 头像和 BOSS 特效叠加。
- 顶部状态信息和底部操作摘要。
- 文字版降级信息生成。

主要类型：

- `MysticMapRenderModel`
- `MysticMapRenderer`

### 现有模块职责

- `domain.py` 保留境界、战力、装备、奖励、功法、阵盘、符箓、战技、神通和普通斗法计算能力。
- `__init__.py` 负责 NoneBot 指令、群聊与私聊消息发送、定时任务调度和领域服务调用。
- `storage.py` 提供共享副本、成员索引、战斗子会话、投票和奖励流水的原子读写。
- `cards.py` 保留通用面板和普通斗法战报，不加入秘境地图绘制细节。
- `admin.py` 提供秘境副本配置 API。
- `webui/` 提供可编辑的秘境副本配置界面。

## 持久化模型

共享副本不能存放在单个玩家记录中。`MysticDungeonRun` 以 `run_id` 为主键持久化，玩家记录只保存活动副本索引，私聊路由同时保存 `user_id -> run_id -> source_group_id` 关系。

```text

```

所有截止时间保存为绝对时间。内存定时任务只负责及时触发，持久化状态和绝对截止时间才是事实来源。

Bot 启动时扫描活动副本并恢复房间、分岔、应战、配装、战斗、救援和投票任务。若截止时间在停机期间已经到期，启动后按照原截止时间执行超时结果，不重新给予完整时长。玩家再次操作时也执行惰性恢复，避免调度任务丢失导致状态卡死。

## 地图模板与动态节点数量

每种秘境拥有一张最多 48 节点的固定模板。每个节点槽包含：

```text
node_id
x
y
depth
activation_size
allowed_kinds
is_safe
is_terminal_candidate
```

每条边包含：

```text
edge_id
source_node_id
target_node_id
activation_size
is_loop
```

节点坐标使用 0 到 1 的归一化坐标。`activation_size` 指定节点或边从哪个地图档位开始启用。支持的地图档位固定为：

| Boss 境界索引 | 节点数 |
| --- | ---: |
| 0-4 | 24 |
| 5-9 | 28 |
| 10-14 | 32 |
| 15-19 | 36 |
| 20-24 | 40 |
| 25-29 | 44 |
| 30 及以上 | 48 |

Web 后台可以修改境界区间与节点档位映射，但节点数必须来自上述七个受支持档位。

后台同时提供 `min_map_size` 和 `max_map_size`。两者必须从七个受支持档位中选择，默认分别为 24 和 48。境界映射结果限制在该区间内，不能配置模板未支持的任意节点数。

每个档位必须满足：

- 起点到 Boss 节点必定连通。
- 普通秘境保持中等分岔，24 节点约 3 个分岔，48 节点约 5 个分岔。
- 高风险秘境使用更高分岔密度并增加有限环路。
- 环路不能成为通往 Boss 的唯一通道。
- 每个活动子图至少包含一个安全节点。

## 节点内容实例化

地图几何和节点内容分离。进入副本时，根据秘境主题、地图种子和后台配置为活动节点分配内容。

固定节点：

- 起点。
- Boss 终点。
- 模板定义的关键补给点。
- 模板定义的精英节点。

随机节点类别：

- `random`
- `combat`
- `resource`
- `trap`
- `rest`

默认概率：

| 地图类型 | 随机 | 战斗 | 资源 | 陷阱 | 休整 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通 | 50% | 20% | 15% | 10% | 5% |
| 高风险 | 35% | 30% | 15% | 15% | 5% |

实际概率由全局基础值、危险度、Boss 境界和单秘境覆盖共同计算。连续战斗节点默认最多 2 个。

每种秘境主题独立配置：

- 随机事件池。
- 普通怪物池。
- 精英怪物池。
- 资源池。
- 陷阱池。
- 休整事件池。
- Boss 池。
- 奖励类别和倍率。

资源点和奖励型随机事件对每名固定成员分别进行一次个人奖励抽取，写入各自临时奖励账本。地图或路线类事件只执行一次并作用于共享副本；明确标记为玩家效果的事件则分别结算到对应成员。

`content_seed` 保存到副本主会话，因此 Bot 重启后节点内容不发生变化。骰子使用独立随机源，不从地图种子派生。

## 副本状态机

主要阶段：

```text
lobby
ready_to_roll
moving
awaiting_branch
resolving_node
awaiting_encounter_response
preparing_battle
battle_turn
awaiting_rescue
awaiting_boss_vote
awaiting_leader_transfer_vote
completed
failed
abandoned
```

基础移动流：

```text
等待投骰
-> 移动
-> 可选的分岔选择
-> 落脚节点结算
-> 等待下一次投骰
```

团队建队流：

```text
队长创建房间
-> 2–3 人加入并准备
-> 校验队长令牌和所有成员状态
-> 原子扣除队长令牌并锁定名单
-> 创建共享地图
```

普通战斗流：

```text
战斗节点
-> 单人自动成为参战者，团队在来源群开放应战
-> 私聊 60 秒配装
-> 单人或多人共享血量战斗
-> 胜利后清除节点并返回地图
-> 团队首批失败后由未参战固定成员接力
-> 全体固定成员失败后进入 PVE 求救
```

Boss 流：

```text
Boss 节点
-> 私聊 60 秒配装
-> 单人以 H 血量直接战斗，胜利则结算，失败则结束副本
-> 团队以 N 个血量分段并行战斗
-> 全部分段归零后提交临时奖励
-> 团队存在未完成分段时发起续战投票
-> 存活成员协助剩余分段
-> 全队 0 血或投票失败时结束副本
```

## 指令与交互

具体命令名称沿用现有入口风格，至少覆盖以下能力：

- `秘境`：选择单人或团队入口，或查看当前副本。
- `创建秘境队伍`：在群中创建普通或高风险队伍。
- `加入秘境队伍`、`秘境准备`、`开始秘境`：完成团队房间流程。
- `秘境地图`：重新发送当前完整地图。
- `投骰`：投掷 1 到 6 点并开始移动。
- `选择路线 编号`：在分岔点继续消耗剩余移动点数。
- `应战`：报名普通遭遇战、Boss 续战协助或救援。
- `普通攻击` 或可用战技、神通名称：提交当前私聊战斗行动。
- `自动战斗`：满足境界条件时让 Bot 接管玩家行动。
- `秘境续战 同意/拒绝`：参与 Boss 续战投票。
- `秘境转让队长 @成员`：在队长超时后发起控制权转让投票。
- `秘境救援 金额`、`接取救援 编号`：使用既有真实 PVE 求救流程。
- `退出秘境`：单人直接放弃；团队转为整队放弃确认，不允许单独移除固定成员。

所有地图移动和团队决策在来源群完成。所有配装、回合行动、自动战斗和怪物反击在私聊完成，私聊结果通过持久化路由写回对应来源群副本。

## PVE 战斗基础

### 复用普通斗法

从现有普通斗法中抽取底层回合结算能力，复用：

- 最大血量和灵力。
- 战力、伤害、防御和速度。
- 装备、符箓、功法、阵盘和傀儡效果。
- 战技、神通、冷却和资源消耗。
- 战报图片数据结构。

现有 PVP 普通斗法指令和行为保持兼容。秘境只新增 PVE 参与者协调、怪物 AI 和持久化状态，不在领域计算中复制另一套伤害公式。

### 配装

- 普通遭遇战、Boss 首战、Boss 续战和救援均有 60 秒配装期。
- 配装期允许使用现有装备指令。
- 配装截止时创建个人战斗快照。
- 战斗开始后的换装不影响当前战斗子会话。
- 未在截止前完成配装确认时使用截止时的当前有效装备快照。

### 手动回合和怪物 AI

- 每名玩家每次行动有 60 秒截止时间。
- 玩家行动结算后，若其正在攻击的怪物或 Boss 分段仍存活，Bot 立即控制怪物反击该玩家。
- 玩家行动超时后，Bot 从该玩家当前可用行动中选择合法默认行动。
- 怪物 Bot 根据血量、灵力、冷却和战斗流派选择行动。
- 不设置最大回合数。
- 共享战斗中，每名当前存活参与者完成一次行动后视为一个共享回合结束。
- 每经过 10 个共享回合提高双方伤害倍率，避免治疗或防御形成永久僵局。
- 每次私聊行动发送简洁战况，战斗结束时发送完整斗法战报图。

### 自动战斗

- 仅当玩家境界索引严格高于当前怪物或 Boss 境界索引时开放。
- 自动战斗只接管发起者自己的行动，不替其他团队成员做出选择。
- 自动行动仍逐步写入共享血量并触发怪物反击，不能绕过并发锁直接写最终结果。
- 自动战斗与手动战斗使用同一属性、AI、奖励和失败规则。

## 普通遭遇战

单人副本落到普通战斗节点后，玩家自动成为参战者并直接进入私聊配装。团队副本落到普通战斗节点后，Bot 在来源群展示敌人信息并开放默认 60 秒应战窗口，固定成员可以一人或多人报名。

- 团队无人应战时节点保持未解决，队长不能继续投骰。
- 报名结束后，应战者分别进入私聊配装。
- 所有应战者攻击同一条共享怪物血量。
- 每名玩家完成一次有效行动后，怪物立即反击该玩家。
- 玩家被击败后退出当前批次，其他存活参与者继续战斗。
- 怪物血量归零后立即停止接受新行动，并通过唯一结算键完成一次击杀结算。

团队首批应战者全部失败但怪物仍有血量时：

- 来源群再次开放应战。
- 尚未参战的固定成员可以接手。
- 怪物继承剩余血量；新的参与者重新创建自己的战斗快照。
- 下一批次不继承上一批参与者的临时增益、减益、灵力和冷却状态。
- 所有固定成员都失败后，进入原有真实 PVE 求救流程。

单人玩家失败后直接进入相同的真实 PVE 求救流程，不创建团队接力窗口。

普通遭遇战最终胜利时：

- 节点标记为已解决，副本恢复移动状态。
- 至少完成过一次有效战斗行动的固定成员获得该次战斗掉落，即使其此前已被击败。
- 只报名但未完成任何有效行动的成员无奖励。
- 固定成员的掉落写入个人临时奖励账本，Boss 通关后才正式结算。
- 外部救援者按既有救援报酬规则结算，不加入队伍、不分享地图，也不进入团队 Boss 奖励名单。
- 来源群收到战斗结果和更新后的完整地图。

## 普通 PVE 求救

- 普通遭遇战中所有固定成员失败后，保存怪物剩余血量并进入 `awaiting_rescue`。
- 救援等待时间默认 30 分钟，可由后台配置。
- 救援报酬在委托创建时从请求者灵石中冻结。
- 团队副本由当前队长代表副本创建救援委托，并由当前队长支付冻结报酬。
- 救援成功后向救援者支付冻结报酬。
- 委托超时或请求者放弃时退还冻结报酬。
- 救援者有 60 秒配装时间。
- 救援怪物保留剩余血量，但清除临时增益、减益、灵力和冷却状态。
- 救援者从完整血量和灵力开始战斗。
- 救援者失败后委托保持开放，其他玩家仍可接取。
- 同一救援者对同一委托只能尝试一次。
- 救援成功后战斗节点标记为已清除，原副本恢复移动状态。
- 救援超时或整队放弃时，副本失败并清空所有个人临时奖励。

## Boss 战

### 单人 Boss

- 单人 Boss 血量为基础血量 `H`。
- 玩家完成 60 秒私聊配装后进入普通 PVE 回合战斗。
- 胜利后提交该玩家全部临时奖励并完成副本。
- 失败后副本直接失败，不发起团队续战投票。

### 多人 Boss

设单人 Boss 基础血量为 `H`，进入秘境的固定成员人数为 `N`：

- 多人 Boss 总血量为 `H × N`。
- 总血量平均分为 `N` 个分段，每段初始血量均为 `H`。
- 每名固定成员初始负责一个独立分段。
- 所有分段共同属于同一场 Boss 战，只有全部分段归零才算通关。

队伍抵达 Boss 节点后，全体成员进入 60 秒私聊配装阶段。每名玩家攻击自己的分段，行动后 Boss 立即反击该玩家。提前击破分段的成员进入等待状态，不会触发提前结算。

当当前批次所有成员均已完成分段或无法继续行动，但仍有分段未归零时，Bot 在来源群发起默认 60 秒续战投票：

- 2 人队需要 2 票同意。
- 3 人队需要至少 2 票同意。
- 未投票视为不同意。
- 未达到多数时副本失败。
- 若全队当前血量均为 0，则不发起有效续战，副本直接失败。

投票通过后：

- Boss 各分段和所有玩家严格继承上一批次结束时的血量。
- 0 血成员保持倒地，不能行动，也不会获得免费恢复。
- 仍有血量且尚未完成分段的成员继续攻击自己的分段。
- 仍存活且已经完成自己分段的成员可以在来源群应战并选择一个未完成分段协助。
- 多名存活成员可以同时协助同一分段。
- 协助者的伤害写入目标分段的共享血量，Boss 分别反击每名行动者。
- 已经归零的分段保持完成，不会重置或再次生成。

所有分段归零后，Boss 战成功并通过一次原子事务：

- 标记副本完成。
- 向每名固定成员提交其个人临时奖励。
- 向每名固定成员发放团队 Boss 奖励。
- 清理私聊路由、战斗子会话、投票和活动副本索引。

投票失败、全队 0 血或整队放弃时，副本失败并清空所有未提交的临时奖励。

## 队长转让

- 副本保存 `last_leader_action_at`，以队长最后一次有效副本操作为准，不依赖不可靠的在线状态判断。
- 超过后台配置的无操作时限后，非队长固定成员可以提名一名固定成员接管。
- 2 人队由唯一剩余成员同意即可转让。
- 3 人队要求另外两名固定成员均同意。
- 投票截止前原队长恢复有效操作时，转让投票取消。
- 转让成功后只更新 `leader_id` 和时间戳，不重新扣令牌、不重建地图、不重置战斗。

## 团队放弃

- 正式开本后成员不能单独退出或移除自己的固定席位。
- 任一固定成员可以在来源群发起整队放弃投票。
- 2 人队需要 2 票同意，3 人队需要至少 2 票同意。
- 投票通过后副本进入 `abandoned`，清空所有未提交的临时奖励并清理活动索引。
- 投票未通过时保持原副本阶段，不改变地图、血量或奖励。

## 奖励与令牌

- 使用现有可堆叠物品“普通秘境令牌”和“高风险秘境令牌”。
- 令牌存放在现有玩家奖励背包结构中，不新增独立货币字段。
- 单人副本由玩家消耗一枚对应令牌。
- 团队副本只由队长消耗一枚对应令牌，其他固定成员不消耗令牌。
- 房间未达到 2 人、准备校验失败、地图创建失败或状态保存失败时不扣除令牌。
- 资源点和奖励型随机事件为每名固定成员独立抽取个人奖励。
- 普通战斗掉落只发给至少完成一次有效行动的参战者。
- 团队 Boss 奖励在通关时发给全部固定成员。
- 副本进行中不修改玩家正式背包、修为或灵石。
- Boss 胜利后通过单次原子操作提交全部个人临时奖励。
- Boss 失败、主动退出、救援超时或整队放弃会清空临时奖励。
- 救援报酬不属于临时奖励，使用独立冻结和支付流程。

## 旧版秘境替换策略

不实现旧版“10 次探索”兼容层：

- 删除旧探索次数状态机、旧命令分支和旧事件结算路径。
- 删除仅服务旧秘境的配置、存储方法、定时任务和测试。
- 不读取、不转换旧版进行中秘境状态。
- 不退还令牌，不补发奖励，不保存迁移版本号。
- 部署后旧版活动会话直接失效，新系统只识别新的副本主会话。
- 保留新副本仍使用的令牌物品、通用奖励能力和普通斗法能力，避免误删共享模块。
- 实施验收时检查旧入口、旧状态字段和旧迁移标识不再被运行代码引用。

## 地图渲染与资源

### 背景母版

- 26 种秘境各生成一张 3840x2160 背景母版。
- 每张母版按 48 节点地图构图，能够容纳最大活动子图。
- 背景只包含地貌、建筑、天气和环境光效。
- 背景不得包含节点、路线、文字、人物、怪物或水印。
- 背景由 `gpt-image-2` 生成并逐张验证。

较短地图渲染：

1. 计算活动节点坐标包围盒。
2. 添加安全边距。
3. 扩展为 16:9 裁剪区域。
4. 从 48 节点母版裁剪。
5. 缩放到最终输出尺寸。
6. 在最终画布上绘制连线、节点和状态信息。

### 图层顺序

```text
背景
-> 未探索灰白虚线
-> 已走绿色连线
-> 下一可走红色连线
-> 节点图标
-> 单人或团队八卦阵
-> 团队人数标识
-> Boss 头像
-> BOSS 红色闪电特效
-> 顶部状态
-> 底部操作摘要
```

### 资源目录

建议发布资源目录：

- `assets/mystic_maps/*.png`
- `assets/mystic_dungeon_ui/*.png`

`ui-sprite-runs/` 仅保存生成过程、提示词和验证产物，并保持 Git 忽略。最终选中的资源复制到发布目录后才加入 package-data。

## Web 后台配置

秘境页面新增可编辑区域：

- Boss 境界和节点档位映射，默认 `24/28/32/36/40/44/48`。
- 最小和最大地图档位。
- 普通和高风险秘境入口使用的令牌类型。
- 签到、任务和后台发放令牌数量。
- 全局节点类别概率。
- 危险度和 Boss 境界概率修正。
- 单秘境概率覆盖。
- 普通和高风险地图分岔密度。
- 高风险地图环路数量。
- 连续战斗节点上限。
- 普通怪物和 Boss 的基础血量、属性及奖励倍率。
- 每 10 回合伤害增幅。
- 群内普通遭遇战应战时间。
- 私聊配装时间和玩家行动时间。
- Boss 续战投票时间。
- 队长无操作时限和队长转让投票时间。
- PVE 求救等待时间。
- 26 张背景和地图模板绑定状态。

以下规则固定，不开放为可破坏玩法约束的配置项：

- 团队人数只能为 2–3 人。
- 单人固定消耗一枚令牌；团队固定只有队长消耗一枚令牌。
- 多人 Boss 总血量公式固定为 `H × N`。
- Boss 必须按人数分为 `N` 段，每段初始血量为 `H`。
- 自动战斗要求玩家境界索引严格高于敌人。
- 正式开本后成员名单不能补位或替换。

第一版不在 Web 中编辑节点坐标或连线。

## 一致性、并发与错误处理

- 所有指令先验证当前副本阶段、来源群、成员身份和私聊路由。
- 投骰、选路、应战、战斗行动和投票使用递增序号或唯一操作键防止重复执行。
- 每个副本主会话使用副本级锁；普通共享血量和 Boss 分段使用战斗级锁。
- 玩家伤害、怪物反击、血量归零和奖励写入在同一事务边界内更新。
- 多人同时造成致命伤害时只允许一次击杀、一次节点清除和一次奖励结算。
- 奖励流水以 `run_id + node_id + user_id + reward_kind` 建立唯一结算键。
- 状态先原子保存，再发送图片、群通知或私聊战报。
- 群消息或私聊发送失败不会回滚已经完成的状态结算，用户可以通过查询指令重发当前状态。
- 地图发送失败时可以使用 `秘境地图` 重试。
- 地图渲染失败时发送文字版位置、路线和操作提示，状态不丢失。
- 背景资源缺失时使用通用秘境背景并记录错误。
- 私聊路由缺失时拒绝战斗行动，并提示玩家回来源群重新绑定当前副本。
- 配装、行动、应战或投票超时任务必须幂等，重复触发不产生二次结果。
- Boss 胜利结算使用单次原子操作，避免重复提交临时奖励。
- 后台配置保存前验证概率总和、地图档位、境界范围、倍率、超时和资源绑定。
- 无效后台配置直接拒绝并返回明确字段错误。

## 测试策略

### 地图与移动单元测试

- 七种地图档位节点数量正确。
- 每个模板在每个档位下起点到 Boss 必定连通。
- 普通分岔和高风险环路约束正确。
- 投骰、分岔剩余点数、落脚结算和 Boss 截停正确。
- 固定内容种子可以恢复相同节点内容。
- 已访问环路节点不重复触发奖励。
- 单人和 2/3 人团队使用同一移动规则。

### 组队单元测试

- 只有 2–3 人且全部准备后才能开本。
- 团队只扣除队长一枚对应令牌。
- 状态创建失败时令牌不扣除。
- 开本后名单锁定，不能补位或替换。
- 只有队长可以投骰和选择岔路。
- 成员不能同时进入多个冲突副本或私聊战斗。
- 队长无操作超时、转让投票取消和转让成功规则正确。
- 团队整队放弃使用正确的多数阈值，且不会移除单个固定席位。

### 普通战斗单元测试

- 一人或多人应战时共享同一条怪物血量。
- 每名玩家行动后怪物只反击该玩家一次。
- 并发攻击不会丢失伤害或重复击杀。
- 首批全灭后，未参战固定成员继承怪物剩余血量接力。
- 全体固定成员失败后正确进入 PVE 求救。
- 至少完成一次有效行动的参战者获得掉落，包括此前已被击败者。
- 只报名未行动者不获得掉落。
- 自动战斗资格只比较境界索引并只接管发起者。
- 回合超时、怪物 AI 和每 10 回合伤害增长正确。

### Boss 单元测试

- 单人 Boss 血量为 `H`，失败后不创建续战投票。
- 2 人 Boss 总血量为 `2H`，3 人 Boss 总血量为 `3H`。
- 每个 Boss 分段初始血量始终为 `H`。
- 只有全部分段归零才完成副本。
- 2 人续战需要 2 票，3 人续战需要至少 2 票。
- 续战严格继承 Boss 分段和玩家血量。
- 0 血成员不能行动或免费恢复。
- 已完成成员可以协助未完成分段，多人可以协助同一分段。
- 全队 0 血时直接失败，不创建无效续战。
- Boss 成功时只提交一次全部个人临时奖励和团队奖励。

### 持久化与并发测试

- 在大厅、移动、分岔、应战、配装、战斗、救援和投票阶段模拟 Bot 重启。
- 重启后地图、成员、Boss 分段、怪物血量、截止时间和私聊路由正确恢复。

## 验收标准

- 玩家可以选择单人入口或在群中创建 2–3 人团队入口。
- 团队只扣除队长一枚令牌，开本后成员名单锁定。
- 单人和团队均可进入 24–48 节点的持久化秘境。
- 地图节点数量随 Boss 境界按 Web 档位动态变化。
- 不同秘境具有独立背景、怪物、事件、资源和陷阱内容。
- 投骰、分岔暂停、剩余点数继续和落脚结算符合设计。
- 团队由队长投骰和选路，所有成员同步移动。
- 普通和高风险地图分别满足分岔及环路要求。
