# R-39 第一阶段：秘境经济模型（解锁 R-34 / R-35 / R-41 后半）

> 本文只做**经济侧**定稿：入场额度、活跃度、天机阁加成、存量迁移。
> 卡池 / 遗物 / 平衡表属 R-39 第二阶段，与 R-40 实现同期产出，本文不涉及。
>
> 所有「现状」数字都从代码复现，出处标注到文件行；「方案」数字是待你拍板的候选值。

## 1. 现状实测

### 1.1 入场券：两种秘境令牌

| 项 | 值 | 出处 |
|---|---|---|
| 持有上限 | 每种 **3** 枚 | `domain/mystic_drops.py:413` `MYSTIC_TOKEN_MAX_COUNT` |
| 单局消耗 | **1 枚**，按风险档位分普通 / 高风险 | `mystic_dungeon.py:1814` `_entry_charge` |
| 谁付 | **队长**付，队员不付（队伍 2–3 人） | `mystic_dungeon.py:1720` |
| 入口校验 | 无对应令牌直接报缺令牌 | `mystic_runtime.py:1588` |

### 1.2 周供给（当前版本）

| 渠道 | 期望值 / 周 | 说明 |
|---|---|---|
| 签到 · 普通令牌 | **3.5** | 每日 50% 独立判定（`domain/signin.py:124`） |
| 签到 · 高风险令牌 | **2.1** | 每日 30% 独立判定（同上） |
| 每日任务 · 普通令牌 | **7.0** | 每天随机 1 个任务奖励 1 枚（`domain/economy.py:196`） |
| 垂钓兑换 | **0** | `MYSTIC_FISHING_OPTION_RATE = 0.05` **零读取方**，实际不发 |
| 合计 | **≈ 12.6 局/周** | 全部由队长承担 |

**关键结论：R-34 删掉每日任务后，周供给从 12.6 直接掉到 5.6（腰斩 56%）。**
这就是 R-34/R-35 不能单独上线的量化原因——必须先有新供给模型。

### 1.3 与修为曲线的对照

见 `docs/NUMBERS.md` §4：境 15 之后纯签到已不可能推进，高境全靠副本产出。
秘境是当前**唯一成规模的中后期修为来源**，所以入场额度本质上是「中后期进度阀门」，
不能只按「令牌够不够用」来定，要按「一周能推几境」来定。

## 2. 两个候选方案

### 方案 A：纯额度制（推荐）

删掉「普通/高风险秘境令牌」两种物品，改为玩家记录上的**每周入场额度**：

| 项 | 普通 | 高风险 |
|---|---|---|
| 周基础额度 | 4 | 1 |
| 活跃度 · 本周签到 ≥ 5 天 | +1 | — |
| 活跃度 · 本周完成 ≥ 3 局 | +1 | — |
| 天机阁 · 弟子 | +1 | — |
| 天机阁 · 长老 | +2 | — |
| 天机阁 · 太上长老 | +3 | — |
| **普通玩家周上限** | **6** | **1** |
| **太上长老周上限** | **9** | **1** |

- 额度每周一 00:00（`Asia/Shanghai`）重置，不累计、不囤积；
- 消耗仍由队长承担，队员不扣额度（与现状一致，避免组队成本转嫁）；
- 高风险额度单列，不占普通额度——避免「高风险更赚所以全打高风险」把普通主题废掉。

**优点**：一次改造到底，R-40 不必兼容物品；不会有「背包里躺着 3 枚令牌但一周只能进 1 次」的怪状态；后台只需 3 个数值键（基础额度、活跃度档位、身份加成）。
**缺点**：要删物品、要迁移存量、要改前端玩家编辑页与秘境选图页。

### 方案 B：令牌保留 + 周补给

保留令牌物品，只改「怎么来」：

- 每周一自动发放 3 枚普通 + 1 枚高风险（无视上限，直接进背包）；
- 活跃度达标再补 1–2 枚普通；
- 天机阁按档位 +1/+2/+3（同方案 A 的加成表）；
- 存量令牌**原样保留可用**，不折算、不补偿。

**优点**：迁移几乎为零（只是改发放入口），前端与选图页不用动；风险最低。
**缺点**：两套记账并存（物品 + 周补给），玩家会出现「有令牌但本周已领完」的困惑；持有上限 3 会让周补给被动卡住（要么取消上限，要么允许溢出，两种都有解释成本）；R-40 仍要处理令牌物品与 UI。

## 3. 共同项（无论选 A 还是 B）

### 3.1 天机阁加成

`TIANJI_ENTRY_BONUS` 取代已退役的 `TIANJI_COOLDOWN_DAYS`，与合欢宗 `HEHUAN_DAILY_LIMITS`（1/2/5 次，不动）完全隔离：

| 身份 | 周加成（普通额度） |
|---|---|
| 天机阁弟子 | +1 |
| 天机阁长老 | +2 |
| 天机阁太上长老 | +3 |

线上实测持有者 **2 人**（`3305167706` 长老 / 76 天、`1060217609` 弟子），自动获益，无需补偿。
数值先按上表上线，**观测两周后调**——如果他们因为加成而显著领先，优先降档而不是加额度。

### 3.2 存量迁移

| 情况 | 处理 |
|---|---|
| 背包内有未消耗令牌（实测线上全为 0） | 方案 A：1 枚 = 1 次对应风险额度，并入首周，单周上限 10 次；方案 B：不动 |
| 在途秘境局 | 按 v4.1 决议**直接关闭**、不补偿，清理救援/投票/结算关联状态并记审计 |
| 幂等结算记录（1 人） | 保留审计，不重放 |

### 3.3 配置键

**已退役（无需再做）**：`signin_normal_token_count`、`signin_high_risk_token_count`、
`daily_task_normal_token_count`、`daily_task_high_risk_token_count` 四个键在 R-18/R-23
批次已从 schema、后台表单与前端类型中移除，旧配置文件由
`config_schema.RETIRED_MYSTIC_CONFIG_KEYS` 在加载时裁掉。

**需新增**（方案 A / B 都需要）：
`mystic.weekly_base_entries_normal`、`mystic.weekly_base_entries_high`、
`mystic.activity_signin_days_threshold`、`mystic.activity_entry_bonus`、
`mystic.activity_runs_threshold`、`mystic.activity_runs_bonus`。

## 5. 决策（2026-11-14 已定稿）

| 决策点 | 结论 |
|---|---|
| 入场机制 | **方案 A：纯额度制**。删除「普通/高风险秘境令牌」两种物品，改为玩家记录上的每周额度 |
| 周基础额度 | **普通 4 + 高风险 1**（活跃度各 +1 后普通 6；天机阁太上长老普通 9） |
| 高风险额度 | 单列，不占普通额度 |
| 谁付 | 队长付，队员不扣（与现状一致） |
| 重置 | 每周一 00:00（`Asia/Shanghai`）重置，不累计、不囤积 |
| 存量令牌 | 1 枚 = 1 次对应风险额度，并入首周，单周上限 10 次 |
| 天机阁加成 | 弟子 +1 / 长老 +2 / 太上长老 +3（仅普通额度），观测两周再调 |

方案 A 的周上限：普通玩家 6 次、天机阁太上长老 9 次、高风险恒为 1 次。

## 7. 观测指标（上线后两周）

不做「预期回收率」这类拍脑袋数字，改为观测四条：

1. **周开局数 / 活跃玩家**：目标 3–6 局；低于 2 说明额度太紧，高于 8 说明产出过剩。
2. **额度用尽率**：有多少玩家在周末前打满。长期 100% 说明额度是硬瓶颈。
3. **高风险占比**：目标 20–35%。低于 10% 说明高风险性价比不足（该调奖励，不是调额度）。
4. **队长集中度**：前 3 名玩家承担的开局比例。超过 50% 说明额度没解决「只有少数人有票」的问题。
